# NTV 経理運用ルール (keiri エージェント参照用)

エージェントが判断に迷ったときに最初に参照するファイル。実務で確定したルールのみを記載し、未確定のものは「TBD」と明記する。

## データ取扱原則

1. **バックアップ必須**: 既存収支管理シートを編集する前に、必ず `keiri/data/archive/<YYYY-MM-DD>/<filename>` に元ファイルを退避する
2. **数式・条件付き書式の保護**: openpyxl で操作する際は数式列を上書きしない。条件付き書式 (X概→黄背景+赤文字 など) を壊さない
3. **数値**: 1 円単位。端数処理が必要な場合はユーザーに切上 / 切捨 / 丸めの方針を確認
4. **3 分割等で割り切れない金額**: 合計が一致するように調整する (最終行で帳尻合わせ)

## 取込フロー (AXROSS → 収支管理シート)

1. `keiri/data/input/` 配下に AXROSS 出力 Excel が置かれる
2. ファイル名・列構成・業務単位コードを確認
3. テンプレ (`keiri/templates/11Y5471_template.md`) と突合してマッピング
4. 差分プレビューを生成 (追加 / 更新 / 削除件数 + 上位サンプル)
5. **ユーザーに承認を求める** (差分を提示)
6. 承認後にシート更新、バックアップ作成、結果を `keiri/data/output/` に出力

## 月次クローズ判定

月末の「概処」記入は以下を満たした場合のみ提案する:

- すべての概算が同月内で X概 または実伝で打ち消されている
- 実績計上行に対応する証憑 / 起票日が記入済み
- 予算超過カテゴリがある場合は、ユーザーに事前周知済み

満たさない場合は「未クローズ項目」として一覧化する。

## 費目分類の判断

新規取引が入った場合の費目候補は次の優先順位で決める:

1. 過去の同一取引先 / 摘要での処理パターン
2. `keiri/docs/用語集.md` の費目分類定義
3. ユーザーへ複数候補を提示して確認

未確定で時間切れになる場合は「雑費」に仮置きせず、**未分類フラグ** で別管理する。

## 大型案件 (シーズン 2 方式)

年度予算を大幅超過する案件は次のように扱う:

- カテゴリ確定済み → 入力用シートに正式行として追加
- カテゴリ未確定 → サマリーシートに「【参考】」セクションとして表示し、確定後に正式行へ移動
- いずれも `keiri/docs/案件ログ.md` (TBD) に経緯を記録する

## トラブル時の優先順位

1. ユーザーに確認 (最優先)
2. 本ファイル + `keiri/docs/用語集.md`
3. 過去の処理パターン
4. 複数候補をユーザーに提示

**勝手に推測して進めない**。

## 既知の落とし穴

- シート名に半角スペース混入 (例: `【入力用】11Y5818(2026)  `) — 厳密一致で扱う
- SUMIFS の参照範囲は 2-1000 行
- 月別ブロックは各月 11 列構造 (最終実績 / 概算戻し / 実績 / 概算 / 実績備考 / 空 / 担当 / 処理 / 起票日 / 処理 / 起票日)
- 取引先名の表記揺れ (株式会社の有無、半角 / 全角)
